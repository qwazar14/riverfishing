# §breeding — shared contracts between the parallel work streams (0.9.0)

Four streams build this at once. Each owns files; where one needs another's code it calls EXACTLY the
signatures below. Nobody runs gradle; the integrator builds all three trees at the end. All code is
written in the 1.21.1 dialect (main tree); the integrator ports.

Rules for every stream:
- New classes go in NEW files. Edits to EXISTING files go through an idempotent python patch script
  saved as `tools/patches/p_<stream>.py` taking `<repo root> [1211|1201|26]`, using anchor
  replacement (`sub1(old, new)`, exit 1 with the missing anchor printed) and a `§<stream>` marker so a
  rerun is a no-op. Dialect: 26.x NBT getters are `getStringOr(k, "")`, `getIntOr(k, 0)`,
  `getLongOr(k, 0L)`, `getBooleanOr(k, false)`, `getByteOr(k, (byte) 0)`, `getCompoundOrEmpty(k)`,
  `getListOrEmpty(k)`; `ServerPlayer.serverLevel()` is `sp.level()`; `displayClientMessage(c, true)`
  is `sendOverlayMessage(c)`, `(c, false)` is `sendSystemMessage(c)`; `ResourceLocation` is
  `Identifier`; `Villager` is in `net.minecraft.world.entity.npc.villager`. 1.20.1: NBT/messages as
  1.21.1, items store NBT through `com.riverfishing.item.StackNbt` in all versions (use it, never
  `getTag()` / DataComponents directly).
- Lang keys: do NOT edit the lang JSON files. Write your keys to `tools/patches/lang_<stream>.json`
  as `{"en_us": {...}, "ru_ru": {...}, "uk_ua": {...}}` with identical key sets; the integrator
  merges. Russian and Ukrainian must be real translations.
- Item icons: 16x16 PNG generated by a python script `tools/gen_<item>_icon.py` in the style of
  `tools/gen_contract_icon.py` (raw zlib PNG writer, palette constants), written to
  `common/src/main/resources/assets/riverfishing/textures/item/<id>.png`, plus
  `models/item/<id>.json` = `{"parent":"minecraft:item/generated","textures":{"layer0":"riverfishing:item/<id>"}}`.
- Registration of NEW ITEMS is owned by stream B (ModItems.java). Streams C and D name their item
  classes here and B registers them; the classes must exist with the constructor `(Item.Properties)`.
- Comments explain WHY (the convention in this codebase); `ponytail:` marks a known ceiling.

## Stream A — calendar and spawning windows (`engine/Calendar.java`, profiles)

```java
package com.riverfishing.engine;
public final class Calendar {
    public enum Sub { EARLY, MID, LATE }              // 8 days each; 24 per season; 96 per year
    public static Season season(Level level);        // Serene Seasons when present, else own
    public static Sub sub(Level level);
    public static int dayOfYear(Level level);         // 0..95
    public static int daysUntil(Level level, Season s, Sub sub);   // 0 when inside it
    public static boolean inWindow(Level level, FishProfile p);    // p.spawnSeason/p.spawnSub, sub may be null = whole season
    public static Component name(Season s, Sub sub);  // "late spring"
}
```
`integration/SeasonProvider.getSeason(level)` keeps returning Serene Seasons' season when the mod is
present; when absent it now returns `Calendar`'s own season instead of null. Everything that
already reads `SeasonProvider.getSeason` (bite engine, crops) therefore gets seasons without SS.

Profiles gain `"spawn": {"season": "spring", "sub": "late"}` (`sub` optional) written by
`tools/add_spawn.py` (a table in the script, defaults by group, overrides per species). Parsed into
`FishProfile.spawnSeason` (Season, never null — default by group) and `FishProfile.spawnSub`
(Calendar.Sub or null).

## Stream B — genome, roe, fry, the aquarium (`fish/Genome.java`, `item/RoeItem`, `item/FryItem`, `block/Aquarium*`)

The genome string already on every fish card (`Card.Genes`, e.g. `"Ss Cc VV ff"`, loci S size,
C colour, V vigour, F fertility) is the ONLY genome format. Stream B adds:

```java
package com.riverfishing.fish;
public final class Genome {
    public static final String LOCI = "SCVF";
    public static String of(ItemStack fish);                  // "" when none
    public static String cross(String mother, String father, Random rng);   // Mendel: one random allele per locus from each parent, dominant written first
    public static boolean dominant(String genome, char locus); // has at least one capital
    public static boolean pure(String genome, char locus);     // both alleles equal
    public static int clutch(String motherGenome, int motherWeightG, FishProfile p, Random rng);  // fry per spawn: base 10..40 by weight vs mean, FF x1.5, ff x0.6
}
```
Items (registered by B in ModItems, ids `roe` and `fry`):
```java
public class RoeItem extends Item {   // NBT via StackNbt: Species (id string), Genome, Laid (world day), Count (eggs)
    public static ItemStack of(ResourceLocation species, String genome, int count, long day);
    public static ResourceLocation species(ItemStack s);
    public static String genome(ItemStack s);
}
public class FryItem extends Item {   // NBT: Species, Genome, Count (fry in this stack — the item itself does not stack)
    public static ItemStack of(ResourceLocation species, String genome, int count);
    public static ResourceLocation species(ItemStack s);
    public static String genome(ItemStack s);
    public static int count(ItemStack s);
    public static void setCount(ItemStack s, int n);
}
```
Both show the species name in the item name (`item.riverfishing.roe` = "%s roe" pattern with the
species inserted) and a tooltip line with the genome and the count.

Aquarium (existing 2x2 multiblock, master cell holds `AquariumBlockEntity` with up to 3 mounted
fish): becomes a live tank. Rules, all server-side in a block-entity ticker on the master:
- fish inside keep their cards; a ♀ (Card.Sex 0) and a ♂ (Sex 1) of the same species, both size
  class ≥ 2 (Card.Size), spawn when `Calendar.inWindow(level, profile)` AND the tank was fed within
  the last game day (right-click with any item tagged `riverfishing:bait` or the mod's groundbait; the
  tank keeps `FedUntil` = day+1). Spawning takes 3 days of continuous conditions (counter `SpawnTicks`),
  then a RoeItem appears in the tank's roe slot (one at a time) with `Genome.cross` and
  `Genome.clutch` count; taken out by right-click with an empty hand (before the fish).
- a RoeItem put into a tank with NO adult fish incubates: `Incubate` counter, 4 days when the biome
  temperature suits the species (profile biome/temperature preference through the same check the
  bite engine uses if reachable, else always), 8 days otherwise; then it becomes a FryItem with
  `Count = roe.Count * survival` where survival is 0.5 (vv), 0.7 (Vv), 0.9 (VV).
- the tank tooltip / nameplate is out of scope; a `screen`-less design: everything is right-click.
- `AquariumBlockEntity` gains NBT `FedUntil`, `SpawnTicks`, `Roe` (ItemStack), `Incubate`.

Stream B also registers streams C's and D's items in ModItems: `seine_net` (`item/SeineNetItem`),
`cast_net` (`item/CastNetItem`).

## Stream C — wild stocking rework (`fishing/StockedData`, `FishingManager.releaseFish`, the fry net)

Replaces the settle ROLL with a breeding-stock ledger, keyed as today by region + species:
- `StockedData.addBrood(region, species, sex, day)` records a mature released fish (Card.Size ≥ 2);
  `broodPairs(region, species)` = min(♂, ♀); `addFry(region, species, count, day)`; the species is
  SETTLED (markStocked) when EITHER a pair has been in the water through one full spawn window of
  the species (`Calendar.inWindow` false→true→false since the pair was complete) OR ≥ 30 fry were
  released and one window has passed. A release is refused outright only when habitat fit ≤ 0
  (hostile); a settled species still needs fit ≥ 0.5, below it the ledger fills but never settles
  and the message says why.
- fishing a species down to 0% stock in the region before the window closes clears its brood
  (hook where `FishingPressureData.addCatch` is called on landing — patch there, small).
- the release message is a checklist, not a percentage: fish just released, ♀/♂ present, water fit,
  days until the window / until settled. Keys under `message.riverfishing.stock_*`.
- fry release: throwing a FryItem into water (same item-entity path as fish) calls
  `releaseFry(level, pos, species, genome, count)` → `addFry` + `addStock` units (count * 0.02).
- the population's genome: `StockedData.genome(region, species)` = the most recent brood/fry genome
  string (ponytail: last writer wins; averaging later). Stream C exposes it; nothing reads it yet.
- The fry net: the existing `bait_trap` item ("Малявочник") gains a second job — placed/used in water
  of a region where the species has fry (`StockedData.fryCount(region, species) > 0`, fry recorded by
  `addFry` and decaying to adults after one window), it yields a FryItem of up to 10 of that species
  with the population genome, subtracting from the ledger. Find how bait_trap works today and add the
  branch beside it.

## Stream D — nets (`item/SeineNetItem`, `item/CastNetItem`), the pond harvest, the poaching hook

- `seine_net`: crafted (string + sticks + lead? choose sensible vanilla ingredients, add the recipe
  JSON under `data/riverfishing/recipes/`), used by right-clicking water: takes ONE game day to haul
  (use duration like a rod cast; the item sets a cooldown of 1200 ticks) and yields fish from the
  region's SETTLED species proportional to `FishingPressureData.stockPercent` — 1..3 fish, each a
  full fish item via `FishItem.create` with weights drawn like a bite would (use the profile's
  weight range, no card / no angler — a netted fish has NO catch card, which is the point: it was not
  caught). Every haul subtracts stock (`addStock` with negative units is not a thing — call
  `addCatch` per fish).
- `cast_net`: throwable-ish version: right-click water → instant, 0..1 fish, 300-tick cooldown, wears
  (durability 32).
- POACHING: nets are legal only in water YOU stocked. `StockedData.owner(region, species)` (stream C
  records the releasing player's UUID in `addBrood`/`addFry`; stream D reads it — if C's method is
  missing at integration the integrator adds it). Hauling from water you did not stock: the haul
  still happens (this is a simulator — poaching works, that is what makes it wrong) but every fisherman
  within 64 blocks "sees" it: `Contracts` reputation −5 (`PlayerData.root(sp)` int `contract_rep`,
  clamp at 0), a message `message.riverfishing.poaching` in red, and the region's stock takes double
  the catch. Add a guide page `guide.riverfishing.nets` (title + prose, three languages) that says
  plainly: nets empty a water for years, this is why they are banned for anglers, in the mod they
  cost you the fishermen's trust — the educational note the author wants.
- Later (not now): warden/patrol, confiscation. Leave a `ponytail:` note where it would hook in.
